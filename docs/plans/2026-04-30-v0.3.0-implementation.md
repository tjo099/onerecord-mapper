# v0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@flaks/onerecord@0.3.0` — the **publicly verifiable TypeScript implementation of IATA OneRecord 3.2 + API 2.2.0, covering booking-flow and security-workflow classes**. Closes deviations #1 (full), #6, #7 (deeper), #9, #10, #11. Adds the first cargo-domain expansion batch (`SecurityDeclaration` + `RegulatedEntity` + 3 code lists), brings class count to 34. Extends PBT round-trip coverage to all 34 classes. Extends NE:ONE contract testing per-class. Publishes a conformance matrix.

**Architecture:** Eleven-phase delivery. Phase 0 verifies preconditions (NE:ONE still available; ScreeningMethod/SecurityStatus/ScreeningExemption canonical values; stale roadmap cleanup). Phases 1-2 ship the cargo-domain batch (RegulatedEntity → SecurityDeclaration → Shipment/Piece backrefs). Phase 3 closes booking-flow #1+#11 with a forced-order schema rework → state-table rework → transition rewrite. Phases 4-6 close the remaining deviations (#6 cross-node, #7 deeper, #9/#10 default-path). Phase 7 mechanically extends PBT to all 34 classes. Phase 8 extends NE:ONE contract tests per-class. Phase 9 publishes the conformance matrix. Phase 10 hardens the release pipeline. Phase 11 ships.

**Tech Stack:** TypeScript 5.6+, Bun 1.3.x, Vitest 2.1+, Zod 4, fast-check 3.22+, Biome 1.9+. Existing Docker-compose NE:ONE orchestration (added in v0.2) is reused. GitHub Actions for CI/release.

**Spec sources:**
- `docs/roadmap.md` v0.3 section (lines 82-162) — primary scope
- `docs/spec-deviations.md` — deviations #1, #6, #7, #9, #10, #11 (D8 already closed in v0.2; row in roadmap is stale and gets cleaned in Phase 0)
- `docs/plans/2026-04-30-v0.3.0-review-response.md` — three-reviewer findings synthesis; mandatory reading before any phase begins
- IATA-Cargo ontology `https://onerecord.iata.org/ns/cargo` — **pin recommended bumped to 3.2.1** per review response §1.6 (the existing 3.2 pin is internally inconsistent and arguably already wrong since NE:ONE Server serves 3.2.1). Decision pending owner confirmation; if 3.2.1, both `Shipment.securityDeclarations` AND `SecurityDeclaration.issuedForShipment` ship together.

**Estimated duration:** 12-14 weeks from kickoff (70-90 PD) under **Path B** of `docs/plans/2026-04-30-v0.3.0-review-response.md`; 14-16 weeks (80-100 PD) under **Path A**. Original 10-week / 50-65 PD estimate was revised upward after three-reviewer pass discovered (a) significant unscoped cross-node walker work (Phase 4), (b) NE:ONE per-class endpoint audit + downscoping (Phase 8), and (c) PBT runtime budget reality. Phases overlap where dependencies allow; serial-only critical path is Phase 0 → 1 → 2 → 3, Phase 4 in parallel from week 5, Phase 7 starts week 8, release infrastructure overlaps from week 10.

import type { ParseError } from '../error/parse-error.js'

export function checkAwbConsistency(
  rootClass: string,
  root: Record<string, unknown>,
): Extract<ParseError, { kind: 'cross_node_constraint_violation' }> | undefined {
  if (rootClass !== 'Waybill') return undefined
  const waybillAwb = root['waybillNumber']
  const shipment = root['shipmentInformation']
  if (typeof shipment !== 'object' || shipment === null) return undefined
  // shipment may be an IRI ref or an embedded object
  if (Array.isArray(shipment)) return undefined
  const shipmentAwb = (shipment as Record<string, unknown>)['awbNumber']
  if (
    typeof waybillAwb === 'string' &&
    typeof shipmentAwb === 'string' &&
    waybillAwb !== shipmentAwb
  ) {
    return {
      kind: 'cross_node_constraint_violation',
      constraint: 'awb_inconsistency',
      path: '$.shipmentInformation.awbNumber',
      details: { waybill: waybillAwb, shipment: shipmentAwb },
    }
  }
  return undefined
}
