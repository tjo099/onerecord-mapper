# v0.6.0 Quote & Book Charge Chain Implementation Plan (r2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@flaks/onerecord` 0.6.0. It adds the ONE Record 3.2
`Price`, `Ratings` and `TransportLegs` classes, nine embedded shapes, and
complete ontology property sets on `BookingOption`, `BookingRequest` and
`Booking`. Every payload that 0.5.0 accepted keeps parsing, and a guard test
diffs all of it against the vendored ontology.

**Architecture:** Zod schemas in the existing per-class codec architecture:

- one directory per LogisticsObject class, `src/classes/<kebab>/`;
- internal embedded shapes in `src/classes/shared/distribution.ts`;
- registration in the `CLASSES` map. The facade, mapper and `CODECS` all derive from it.

Correctness rests on three tests: a guard that diffs the schemas against
IATA's own TTL files, a property test that uses the published 0.5.0 package
as its oracle, and a chain integration test.

**Tech Stack:** TypeScript 5.9 (`strict`, `exactOptionalPropertyTypes`,
`noUncheckedIndexedAccess`), Zod 4.3, Vitest 4, fast-check 3, Biome 1.9,
bun 1.3.

**Spec:** `docs/specs/2026-11-13-v0.6.0-spec.md` (r3 plus errata) is
normative. Every schema's exact field list and Zod encoding is in spec
§2–§5. Each task cites a spec section instead of repeating it. Design:
`docs/specs/2026-11-13-v0.6.0-design.md`. Review history:
`docs/plans/2026-11-13-v0.6.0-spec-review-response.md` and
`docs/plans/2026-11-13-v0.6.0-plan-review-response.md`.

## Global Constraints

- The ontology pin stays 3.2.0, so `CARGO_ONTOLOGY_VERSION` stays `'3.2.0'`. Line citations (`Lnnnn`) refer to the official `2025-07-standard` file at IATA commit `49e8ac1bfdc24d76fddf307e87f36e381b6941b1`.
- Wire profile:
  - references are bare IRI strings (`safeIri()`);
  - codes are bare tokens;
  - `xsd:dateTime` values carry a timezone (`z.string().datetime({ offset: true })`).
- Every object schema is `.strict()`.
- Arrays are `z.array(...).optional()`. An empty `[]` is rejected after parsing as `cardinality_violation`.
- No new runtime dependency. The oracle devDependency `onerecord-0-5-0` (`npm:@flaks/onerecord@0.5.0`) is installed by the controller before Task 1. Tasks import it; they never install it.
- No new `ParseError` kind.
- The existing `test/snapshots/classes/booking*.snapshot.json` files stay byte-identical.
- In the three chain classes, existing keys keep their 0.5.0 relative order. New keys are appended after them.
- New classes copy `src/classes/co2-emissions/*`, including the serialize message `SerializationError[invalid_application_object]: serializeX: invalid input`. Run `bun run lint:fix` after copying, because the renamed imports come out unsorted.
- **Snapshot determinism.** Factories set every IRI field with a fixed UUID: `testIri('<Class>', '00000000-0000-0000-0000-0000000000NN')`. `testIri` defaults to `randomUUID()`, which makes snapshots flaky.
- Every `@deprecated` JSDoc sits on its own line or lines, directly above its key, in both the schema shape and the hand-written type. Never put the JSDoc on the same line as the key.
- Negative tests pin the reason. A `zod_validation` test asserts the first issue's `path` (and `code`, where the spec names one: `unrecognized_keys` for G4d), not just `kind`.
- `bun run test` alone is NOT a green signal. Every task ends with `bun run typecheck && bun run lint && bun run test`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never tag, push or publish.

## Review Focus

These are the input classes most likely to bite users that the spec leaves
implicit. Each is pinned in the task named.

1. **Mixed fleet.** Skidd and Booking Portal stay on 0.5.0. A legacy-shaped object serialized by 0.6.0 must be byte-identical to what 0.5.0 serializes. Task 8 pins this against the oracle's serializers.
2. **A single value for a multi-valued property.** JSON-LD peers often send a scalar, for example `Booking.additionalInformation: "text"`. The result must be `zod_validation` at path `additionalInformation`, and the profile doc must explain why. Pinned in Task 5 and documented in Task 14.
3. **Datetime timezone variants.** Every `xsd:dateTime` field accepts `…Z` and `…+02:00` and rejects a value with no timezone. Pinned for all nine datetime fields by the guard in Task 12, plus explicit tests in Tasks 4 and 7.
4. **Reference IRIs are canonicalised, `@id` is not.** `safeIri` lowercases scheme and host and adds `/` for an empty path, but leaves `@id` untouched. A join from `Price.ratings` to a Ratings `@id` misses when a peer uses an uppercase host. Under the graph walk, the same payload is `iri_not_canonical`. Pinned in Task 13 and documented in Task 14.
5. **Free text that looks like an IRI under the graph walk.** `"NOTE: prepaid"` in `remarksText` must not trigger `iri_not_canonical`. This needs the `looksLikeIri` whitespace fix (spec §6 erratum). Pinned in Tasks 10 and 13.
