## 2. Conventions (all MUST unless stated)

### 2.1 Field encodings

| Ontology range kind | Zod encoding | Precedent |
|---|---|---|
| LogisticsObject class, max 1 | `safeIri().optional()` | every existing class |
| LogisticsObject class, many | `z.array(safeIri()).optional()` | `Waybill.waybillLineItems` |
| Embedded class (§3), max 1 | `<Shape>Schema.optional()` | `Waybill.declaredValueForCarriage` |
| Embedded class, many | `z.array(<Shape>Schema).optional()` | `Waybill.destinationCharges` |
| Closed small code list / enumeration | named `z.enum` from `src/codes/enums.ts`, `.optional()` | `spec-deviations.md` #17 |
| Large or open code list, `:CodeListElement` | bounded `z.string()` identical to the existing field of the same code list (table §2.2) | `WaybillLineItem.rcp` |
| `xsd:double` | `z.number().optional()` (Zod 4 rejects `NaN`/`±Infinity`; no sign constraint) | `CurrencyValue.numericalValue` |
| `xsd:boolean` | `z.boolean().optional()` | `BookingPreferences.flexibleDates` |
| `xsd:dateTime` | `z.string().datetime({ offset: true }).optional()` | `BookingOption.expiresAt` |
| `xsd:string` | `z.string().min(1).max(N).optional()`, `N` from §2.2 | `Waybill.shippingRefNo` |

Arrays: `[]` is rejected post-parse as `cardinality_violation` (existing
`findFirstEmptyArray`, recursive into embedded objects); serializers strip
empty arrays (`omitEmpty`). No new array rules.

Every object schema is `.strict()`. Unknown keys → `zod_validation`
(`unrecognized_keys`).

### 2.2 Bounds and code-list string types (one type per code list)

| Ontology range | Encoding | Same as |
|---|---|---|
| `codes:ChargeCode` | `z.string().min(1).max(16)` | `Waybill.carrierChargeCode` (L479, same range) |
| `codes:OtherChargeCode` | `z.string().min(1).max(16)` | `OtherCharge.otherChargeCode` |
| `codes:RateClassCode` | `z.string().min(1).max(8)` | `WaybillLineItem.rateClassCode` (L2068) |
| `:CodeListElement` (`rcp`, `uldRateClassType`, `productCode`, `serviceLevelCode`) | `z.string().min(1).max(16)` | `WaybillLineItem.rcp`, `.uldRateClassType` (L2664) |
| `codes:CurrencyCode` | `z.string().min(1)` | `CurrencyValue.currencyUnit` |
| `codes:*UnitCode` (dimensions, temperature, volume, weight) | `z.string().min(1)` | `Value.unit` |
| waybill prefix / number | `z.string().regex(/^[A-Z0-9]{1,3}$/)` / `z.string().regex(/^[A-Z0-9]+$/)` | `Waybill.waybillPrefix` / `.waybillNumber` |
| free text: identifiers (`priceReferenceId`, `priceSpecification`, `unitBasis`, `shippingRefNo`) | `max(64)` | `Waybill.shippingRefNo` |
| free text: descriptions (`chargeDescription`, `productDescription`) | `max(256)` | `OtherCharge.reasonDescription` |
| free text: long (`additionalInformation`, `alternatives[]`, `shippingInfo`, `remarksText`) | `max(512)` | `Waybill.accountingInformation` |

String bounds are the package's editorial policy (as for
`waybillPrefix`), not ontology facets; the global `maxStringLength`
safety limit still applies first.

### 5.4 Superset acceptance (design G4) — normative

For each class in §5, with `S05` = the 0.5.0 schema and `S06` = §5:

- **G4a** For every input `x` with `S05.safeParse(x).success`,
  `S06.safeParse(x).success` and `S06.parse(x)` deep-equals `S05.parse(x)`.
- **G4b** An input using only envelope + [O] keys with valid values parses.
- **G4c** An input mixing [O] and [L] keys parses.
- **G4d** An input carrying any [D] key fails with `unrecognized_keys`.

G4a is tested by (i) replaying every existing 0.5.0 booking fixture /
factory output and (ii) a property test that generates `S05`-valid objects
(arbitraries for the 0.5.0 shape, kept in `test/property/` as frozen
legacy arbitraries) and checks G4a.

## 8. Ontology conformance guard (design G5)

### 8.1 Extractor — `scripts/extract-ontology-restrictions.mjs`

Node ≥ 20 ESM, zero dependencies. Usage:
`node scripts/extract-ontology-restrictions.mjs <ttl> <out.json> <Class>...`.
It MUST:

1. Parse class blocks (`:<Name> rdf:type owl:Class ;` … terminating ` .`),
   collecting per `owl:onProperty` the `owl:allValuesFrom` range and any
   `owl:maxCardinality "1"`.
2. Classify each range: `xsd:*` → `literal` (keep the xsd type);
   `codes:*`, `:CodeListElement`, or any class with `owl:oneOf` or a
   (transitive) `rdfs:subClassOf :CodeListElement` → `code`; a class whose
   transitive named `rdfs:subClassOf` chain reaches `:LogisticsObject` →
   `iri`; otherwise → `embedded`.
3. Record each property's declaration line (`:<prop> rdf:type
   owl:(Object|Datatype)Property`).
4. Emit, keys sorted for stable diffs:

```json
{
  "source": { "versionInfo": "3.2-rc2", "versionIRI": "…", "sha256": "…", "generator": "scripts/extract-ontology-restrictions.mjs" },
  "classes": {
    "Price": { "line": 8623, "properties": {
      "chargeCode": { "range": "codes:ChargeCode", "kind": "code", "many": false, "declLine": 511 }
    } }
  }
}
```

Committed outputs (classes: Price, Ratings, Ranges, BookingOption,
BookingRequest, Booking, UnitsPreference, CarrierProduct, StationRemarks):

- `test/fixtures/ontology/quote-book-3.2.0.json` — from the binding file.
- `test/fixtures/ontology/quote-book-3.3.0.json` — from the endorsed 3.3.0
  file (forward-compat evidence).

The TTL files are not vendored.

### 8.2 Guard test — `test/unit/ontology/quote-book-conformance.test.ts`

Inputs: the 3.2.0 extract; `LEGACY` and `DEFERRED` maps declared in the
test (and nowhere else), exactly:

```ts
const LEGACY = {
  BookingOption: ['optionStatus', 'expiresAt', 'preferences'],
  BookingRequest: ['requestStatus', 'requestor', 'preferences'],
  Booking: ['forBookingRequest', 'forBookingOption'],
}
const DEFERRED = {
  BookingOption: ['bookingTimes'],
  Booking: ['bookingTimes', 'bookingSegments'],
}
```

For each of the nine classes, with `keys` = schema shape keys minus
`@context`/`@type`/`@id`, and `onto` = extract property names:

1. `onto − DEFERRED[C] ⊆ keys`.
2. `keys ⊆ onto ∪ LEGACY[C]`.
3. `DEFERRED[C] ∩ keys = ∅`; `LEGACY[C] ∩ onto = ∅`.
4. For each `p ∈ keys ∩ onto`, unwrapping `optional` via Zod 4 `def`:
   `many` ⇔ the field is an array; element kind matches — `iri` ⇒ the
   `safeIri()` pipe; `embedded` ⇒ an object schema; `code` ⇒ enum or
   string; `literal` ⇒ `xsd:double`→number, `xsd:boolean`→boolean,
   `xsd:string`/`xsd:dateTime`→string.

Plus: the 3.2.0 and 3.3.0 extracts' `classes[*].properties` (ignoring
`declLine`/`line`) MUST be deep-equal.
